1. 本專案目的

Cofacts「真的假的」平台上,民眾透過 LINE 回報的可疑訊息持續累積; 其中被回報很多次、卻一直沒人回應的熱門訊息,是最需要被查核的一批—— 它們正在社群裡廣泛流傳,卻缺乏可查的澄清資訊。

本專案建立一套半自動排查流程:以程式定期撈取「熱門可疑訊息 + 尚無有用回應」的交集清單, 由 LLM 依查證 SOP(追溯訊息來源、查核資料正確性、引用數據追到原始出處)產出回應草稿, 全程經人工審核後才以建立者帳號公開回寫到 Cofacts。 下方「實際進度」逐筆公開我們做過哪些排查、回覆連結在哪,供社群與官方團隊檢視。

已排查的回應以「Huang Daniel」帳號公開發表於 cofacts.tw。

以「自動化 + LLM」的方式可以大量、快速地產出查證結果,但目前最缺乏的是協助人工審核(review)的志工——這個環節無法自動化,需要社群的力量一起加入。

2. 處理流程

各步驟細節
  • 抓取清單:cofacts.tw GraphQL ListArticles,條件 = 回報數 ≥2 且無有用回應(即官網「熱門可疑訊息」篩選),依回報人數降序存入本地 backlog.db。
  • SOP 自動過濾:全文只有圖片或影片連結(YouTube、FB 等)、無文字可查證者直接略過(標 skip)。
  • 後台逐筆檢視:本地後台頁面列出每筆摘要與 cofacts 原文連結。
  • 查證三步驟:1. 找訊息原文來源 2. 查證資料正確性 3. 引用數據找原始出處。
  • 產出草稿:判定類型(RUMOR / NOT_RUMOR / OPINIONATED / NOT_ARTICLE),本文 ≤240 字,來源放 reference 欄位;每批 10 篇存檔 drafts/ROUNDn.md,驗字數、抽查連結。
  • 交叉審核(LLM B):草稿交給另一組 LLM(Claude Opus 5)reviewer 檢查——年份標示、數據出處、reference 有效性、判定類型是否合理;結果回給 LLM A 整理修正後,才進入人工審核。
  • 人工審核:作者逐篇 review,confirm 才能送出;有疑問退回重查。全流程唯一人工環節。
  • 上傳回應:GraphQL CreateReply(koa:sess cookie 認證),冪等重送、403 自動退避,每篇間隔 5 秒。
  • 記錄歸檔:DB 標 done、posted_replies 入帳、PENDING.md 記錄 reply ID;本頁「實際進度」由 sync_progress.py 每日重新產生。
